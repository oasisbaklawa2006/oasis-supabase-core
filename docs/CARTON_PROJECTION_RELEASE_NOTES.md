Design decisions to confirm in review: (1) approved rows are immutable, a change is a new version; only retirement is allowed and retired rows are frozen; (2) when several approved versions are simultaneously effective the highest version wins (no overlap exclusion constraint); (3) the v1 projection serves both `slot_unit` and `fixed_ratio` profiles (consumers must handle both `conversion_basis` values; `fixed_ratio` carries `ordered_units_per_slot`, a whole number of ordered units per primary container); (4) `carton_config_ids` is a `text[]` validated by trigger at approval time (no FK possible); (5) profile units must equal the price projection unit or the profile is not served; (6) `service_role` can select/insert/update but not delete or truncate; (7) FORCE ROW LEVEL SECURITY with no policies.
