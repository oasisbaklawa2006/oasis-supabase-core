# Studio media publication containment — Core #484 / Studio #240

Base: Core main a4ec8aafc41afa14717c092e583ebb697fe000ef. No production mutation.

The deployed approval dispatcher writes `payload.file_url` into approved `product_media` without private Storage promotion. Studio #306 holds these approvals in the UI; a direct RPC still reaches the dispatcher. This append-only migration adds a draft-table trigger that rejects an approved create/update with private staging provenance or a private/temporary reference. It also checks the effective target URL, so metadata-only updates cannot approve an existing private object reference. The exception rolls back the whole approval SQL statement, including its earlier master-row insertion/update. Both the wrapper and direct dispatcher are covered.

The hold deliberately rejects percent-encoded references rather than implementing a second URL decoder/Storage authority. A forward hardening migration also rejects URL authorities without a valid host/port, dot-segment paths and backslashes, preventing browser path normalization from turning a public-looking path into a signed Storage route. Forward correction 20261121000000 also blocks private render/image/sign and render/image/authenticated routes and invalid numeric IPv4 authorities, while preserving valid dotted IPv4 and public image transformations. Numeric authorities in ambiguous short forms are conservatively held. Prior migrations are retained byte-for-byte. This can hold a previously accepted encoded durable URL; operators retain the draft for rejection or governed resolution. Existing approved rows are not scanned, changed or removed. Durable HTTP(S) URL-only approval, canonical reviewer checks, rejection and deletion requests stay governed by their existing functions. No Storage API operations, credentials, grants to application roles, Edge deployment or automatic publication are introduced.

## Rollback and limits

No destructive data rewrite occurs. Retain this hold on rollback to older Studio builds. A future forward migration may replace the trigger only after a reviewed, server-authorized promotion contract and compatibility tests prove that draft approval cannot publish a private/signed reference. Do not disable the trigger or restore private approval as a quick rollback. Production monitoring should confirm held drafts remain pending and no partial approved master row persists after errors.

This containment does not implement signed preview issuance, upload/provenance/idempotency, Storage copy/promote, historical public URL retirement, or consumer certification. Core #484 remains open for that lifecycle. It does not change Product Master author, pricing, commercial or cross-app authority. Authenticated role/HTTP acceptance on the matched isolated Preview remains separate from clean-replay pgTAP evidence.
